# ui-design-content-copy: full tip list

36 tips distilled from the STA-518 catalogue (YouTube: @whosajid, kolejain). Grouped by source video. Rationale is the catalogue summary, not a transcript.


## The stupid simple way to learn UI/UX design in exactly 10 minutes (kolejain, 9WVt1CelBfg)
- **Keep headline and body copy short** [landing page] A header of only a few words and a short supporting line communicate the message quickly. Fewer words keep attention on the core idea.
- **Use a high-quality hero image as the main visual** [landing page] The quality of the main image often decides whether a landing page works. A strong asset becomes the focal point of the design.

## Everything you need to know about Mobile App UI’s in 8 minutes (beginner friendly) (kolejain, Gfsd8NNuD9g)
- **Use a full-screen empty state that points to the primary action on first use** [mobile app] A first-run user has no content, so cards inviting them to add items add clutter. A simple full-screen empty state with the plus button highlighted, plus a short popover, guides them more clearly.
- **Design a no-results empty state with imagery, acknowledgment, suggestions, and an exit** [mobile app] A search with no matches needs more than an instruction. Pairing imagery with a clear statement, typo suggestions, and an action to leave the state helps the user recover.

## 5 SaaS UI/UX mistakes that SCREAM you Vibe Code (kolejain, PDcQJOPby1k)
- **Remove duplicated KPI blocks** [SaaS web app] Showing the same stats several times makes the page look generated and wastes space, so each metric should appear once.
- **Remove elements that do nothing** [SaaS web app] A card that looks interactive but has no function misleads users, so it should be cut.
- **Trim pricing tiers to a manageable number** [SaaS web app] Five plans overwhelm buyers and make the differences hard to compare, so fewer options with clear distinctions work better.
- **Make plan names match the customer's scale** [SaaS web app] Renaming the top tier to Enterprise signals that it is for larger needs and sets expectations for the upper limits.
- **Show the actual discount the user gets** [SaaS web app] Stating the real saving is important for trust and makes a discounted plan's value clear.
- **Show what the next plan adds that the current plan lacks** [SaaS web app] Listing the extra features of the upgrade gives a clear reason to move up, a pattern common in tools like Resend and Supabase.
- **Include a billing email and payment method on the billing page** [SaaS web app] These basic billing details belong in one place so users can manage payment without searching.
- **Show a map with shaded regions instead of a bar chart** [SaaS web app] A geographic view with the data beside it gives a richer reading of location-based metrics than a plain bar chart.
- **Use real product imagery and skewed cards on landing pages** [landing page] Screenshots of the product and dynamic cards build trust and presentation quality, which tends to drive conversion more than complexity.

## The one thing vibe coding CAN’T fix about your website (kolejain, RCneB_MQ7qs)
- **Use background imagery to show who the product is for** [landing page] Scattered images of the users' world, such as restaurant items for restaurant software, reinforce the audience at a glance. The visuals say who the product serves before the copy does.
- **Enlarge feature imagery and cut the text around it** [landing page] Bigger visuals with minimal copy let the product show itself. Less text reduces the reading load and keeps the page moving.
- **Show social proof in a lighter, less boxy form** [landing page] Testimonials build trust, but heavy lines and boxed text make them feel dense. Removing the extra structure makes them easier to take in.

## 4 UI Design Hacks to KILL boring designs (kolejain, SfX43uIubj4)
- **Match the playfulness of decoration to the product's tone** [general] A playful product can carry blobs and bright colors, while a professional one needs more realistic imagery. Choosing the level of playfulness first keeps the page's vibe consistent.
- **Write friendly, plain-language copy** [general] Natural wording reads better than corporate jargon and makes the page feel personal. Text is most of a website, so its tone affects how playful it feels.
- **Use 404 pages for playful details** [general] A user who lands on a missing page is already off the expected path, so quirky content there is low-risk. The same personal voice and animation can carry through.

## Everything you need to Design macOS Apps EXACTLY like Apple (beginner friendly) (kolejain, Vy0KKvZJRH8)
- **Show an empty state instead of empty controls** [general] A simple invitation to begin is clearer than filters and tools that have nothing to act on yet.
- **Let search match image content, not just titles** [general] Image recognition lets people find visual items by what they show, which fits an app built around visual content.
- **Surface keyboard shortcuts in a cheat sheet inside settings** [desktop app (macOS utility)] Powerful shortcuts are easy to forget, so a reference placed in settings helps users learn them over time.

## The 4 Levels of Landing Page UI/UX Design (kolejain, eMMiLeo_UGI)
- **Choose stock imagery that relates to the product** [landing page] Generic stock photos that have nothing to do with the product make a page feel like a template. Imagery should explain what the product does.
- **Cut vague, wordy copy and drop redundant company names** [landing page] Long blocks of text go unread, and naming the company beside its own logo adds nothing. Short, specific copy lets visuals carry more of the message.
- **Replace stock images with the real product dashboard** [landing page] A screenshot of the actual product shows what the software does, which is more persuasive than a generic photo. It also suits a dark theme.
- **Give buttons that go to the same place the same label** [landing page] Matching labels on the top and main calls to action tell visitors they lead to the same destination. This builds a correct mental model.
- **Use shorter copy that describes the whole product** [landing page] A brief, punchy headline and subline that summarize the product read faster than long descriptions. This is especially effective at higher polish levels.
- **Add brand elements such as badges, logo sets and proof links** [landing page] Badges, client logos and a link to social proof strengthen trust and brand identity. They help the page feel like a product designed with care.
- **Write copy about how the product helps, not only what it does** [landing page] Describing the outcome, such as turning data into decisions, is more valuable to a buyer than describing the feature. This shift makes copy more persuasive.

## The secret behind weirdly perfect UI designs (kolejain, neE6wOuBIP8)
- **Replace plain text with recognizable icons and diagrams** [general] Icons and diagrams are recognized at a glance, while text has to be read. A card that turns text into visuals is easier to understand even if it shows less raw information.
- **Do not explain an unclear UI harder with extra labels or tooltips** [general] Every added label or tooltip is more information, which makes the screen harder to read. Clearer visuals usually solve the problem better than more explanation.

## The 80% of UI Design - Typography (whosajid, 9-oefwZ6Z74)
- **Design for dynamic content length, not just the static mockup** [general] Numbers and labels change in real data, so a layout that looks right with placeholder text can break with real values. Testing with variable content keeps the design functional.

## The Golden Rule of UI Design (whosajid, 9zt__YPULm8)
- **Treat simplicity as removing what is not needed, not as lacking essentials** [general] A design can be simple and still include the information users need to decide. Minimal is not a goal in itself; the test is whether anything essential is missing.
- **Show essential product details in a compact, scannable form** [e-commerce] Users need enough detail to make an informed decision, but the details should not distract from the main actions. A compact layout keeps the page scannable while still including what matters.

## The Easy Way to Design Premium Websites (whosajid, DBJoepxxQdg)
- **Replace filler copy with specific, concrete statements** [general] Generic slogans could appear on any product's page, so they communicate nothing. Concrete claims about what the product does make the page specific and credible.

## 2 Ways of Building Websites (whosajid, Kkjpvfwhv-c)
- **Use placeholders for data-driven content in app components** [web app] In a web app the content comes from a database, so components only need placeholder slots at design time. This keeps the design independent of real data.

# ui-design-process: full tip list

39 tips distilled from the STA-518 catalogue (YouTube: @whosajid, kolejain). Grouped by source video. Rationale is the catalogue summary, not a transcript.


## The stupid simple way to learn UI/UX design in exactly 10 minutes (kolejain, 9WVt1CelBfg)
- **Copy a design you like exactly to learn its details** [general] Recreating a design faithfully forces you to notice spacing, sizes and padding that are easy to overlook. This builds the habit of seeing decisions behind a design.
- **Keep UI flavor separate from UX journey thinking** [general] Visual flavor changes how a site feels, while the user journey decides how screens are structured. Treating them as two distinct decisions keeps both clear.
- **Give users a way out of onboarding to log in** [general] Many people reach onboarding by accident, so an exit to the login page prevents frustration. It respects users who were not expecting the flow.
- **Decide deliberately whether to block or remind on unverified email** [general] Blocking progress until a code is entered is secure, while a gentle reminder keeps the flow open. Either choice can be right, but it should be made on purpose.
- **Ask for team size early to branch onboarding** [general] Knowing whether the user is an individual or part of a team shapes every later step. Asking early lets the flow adapt, such as skipping team invites for solo users.
- **Build a swipe file of sections that inspire you** [general] Collecting a small set of strong hero and feature sections creates a reference library. Studying them trains your eye for what works.
- **Annotate spacing, hierarchy and grouping in chosen sections** [general] Breaking a good design into its spacing, hierarchy and grouping makes its structure visible. This turns inspiration into understanding.
- **Restyle one layout in two different flavors** [general] Rebuilding the same layout in a warm style and a premium style shows how design feeling can change without changing structure. It is a useful exercise for developing range.

## Every UI/UX Concept Explained in Under 10 Minutes (kolejain, EcbgbKtOELY)
- **Give every user action a visible response** [general] Spinners while loading and success messages after completion tell users the system heard them.

## Everything you need to know about Mobile App UI’s in 8 minutes (beginner friendly) (kolejain, Gfsd8NNuD9g)
- **Educate users before relying on swipe gestures** [mobile app] Swipes are common in modern apps, so they can carry a lot of the interaction, but only if people know they exist. Showing users how a gesture works makes it reliable.

## The 3 dashboard UI flaws that give away you've NEVER built one (kolejain, Ksx9C2-3yMo)
- **Sequence onboarding one step at a time instead of one modal** [general] A single tooltip on the most important action, followed by the next step once it is done, avoids overwhelming new users. A long modal of bullet points is usually forgotten the moment it is dismissed.

## The one thing vibe coding CAN’T fix about your website (kolejain, RCneB_MQ7qs)
- **Let the identity come from what conveys the feeling, not a formula** [general] Brand choices made for the feeling the product should create fit better than rules applied mechanically. The result stays specific to the brand.
- **Combine reference sections to work out message and flow** [landing page] Taking the hero from one site, the logo ribbon from another and the feature layout from a third lets you plan the page's structure before polishing it. This makes the flow deliberate.
- **Sketch a wireframe first and strip it to structure** [landing page] Working at the level of boxes and sections lets you settle the layout before styling. Discarding everything except the wireframe keeps focus on structure.
- **Keep one layout and swap identities to change the feeling** [landing page] A structured layout can take different colors, imagery and type and still feel right in each case. This is how one system produces very different pages.

## Why the best software must LIE to you (kolejain, S8DcTJm8pYM)
- **Delay a primary click only when a secondary action shares the same input** [general] A single click has to wait briefly to rule out a double click, which is the cost of having two actions on one target. Separate buttons avoid this ambiguity, which is why phone controls respond instantly.
- **Skip the delay when the actions do not compete** [general] Selecting a table cell is needed no matter what, so it can highlight immediately while a double click still edits. Adding a delay here would only make the interface feel slower.
- **Design around the paths people actually take** [general] The paved paths on the Iowa quad followed where students already walked. Watching real behavior tells you where the interface should be shaped to match it.
- **Move deleted items to a Recently Deleted list before final removal** [general] A recovery list gives users a safety net without an interruption at the moment of deletion. Permanent removal happens later, after a grace period.
- **Show a sent state immediately and delay the actual send for undo** [general] Gmail reports the email as sent right away, while the real send waits a few seconds, leaving time to undo. The delay feels invisible because the feedback is instant.
- **Provide version history to recover from autosaved changes** [general] Once cancel disappears, users still need a way to go back. A version history covers unwanted saves and deletions, and it only needs to be used occasionally.
- **Choose the interaction pattern by how sure the software is of intent** [general] Waiting, inferring, or acting first each assume a different level of certainty and cost time, certainty, or trust. Matching the pattern to how confident you are about the user's intent keeps the interface from over- or under-assuming.
- **Let Escape cancel an action until it is committed** [general] Command-tab on macOS commits only on release and can be cancelled with Escape before that. Letting the user back out of an in-progress action keeps them in control.

## Everything you need to Design macOS Apps EXACTLY like Apple (beginner friendly) (kolejain, Vy0KKvZJRH8)
- **Design the surfaces that live outside the main window** [desktop app (macOS utility)] Popovers, extra windows, and notifications are part of the native experience, so they need the same design attention as the main screen.
- **Make the app feel like a system service, not a destination** [desktop app (macOS utility)] A tool that appears where the user needs it feels native, while a standalone destination makes them leave their current task.
- **Summon the app on demand and let it get out of the way** [desktop app (macOS utility)] Like Spotlight or Raycast, a window that appears when called and dismisses immediately keeps the user in their flow.
- **Update the UI optimistically while saves run in the background** [general] Showing success immediately makes the app feel fast, and the pattern matches Apple Mail moving items to trash before the server confirms.
- **Make drag and drop work into and out of the app** [desktop app (macOS utility)] Effortless content movement, such as dragging items into other apps, is a core expectation on macOS.

## The 4 Levels of Landing Page UI/UX Design (kolejain, eMMiLeo_UGI)
- **Rely on attention to detail rather than heavy illustration or 3D** [landing page] Polish comes from careful craft in layout, motion and type, not from custom illustrations or 3D effects. This makes high-quality results achievable for most designers.

## Original Ideas are Overrated (whosajid, 41IMbwQR-dc)
- **Put usability ahead of originality** [general] The speaker argues that design succeeds on usability, while originality should appear only in small details. Choosing a clear, familiar interaction first keeps the interface usable.

## The Golden Rule of UI Design (whosajid, 9zt__YPULm8)
- **Make every click and scroll feel effortless** [general] Users should be able to tell what matters, what an icon does, and where to find help without pausing. Any moment of uncertainty is a point where the design has failed.
- **Map a user flow to shorten the path to the goal** [e-commerce] Drawing the shortest path from entry to purchase shows where users would click too many times. Designing around that path removes unnecessary steps.
- **Detect the user's location to show delivery information automatically** [e-commerce] Pre-filling the zip code lets the page show a relevant delivery notice without requiring input. Removing a step helps the user complete the purchase.
- **Settle design debates with usability tests against target users and competitors** [general] Watching real users complete a task in your app and a competitor's shows which design performs better. Test results give stakeholders evidence rather than opinions.

## 23 Hacks about Building Websites (whosajid, AmY3db_Qs94)
- **Convert images to WebP for smaller files** [general] WebP keeps the same visible quality at roughly half the file size, so pages feel faster to load.
- **Add a favicon in the site root** [general] Browsers request a favicon automatically, so providing one in the root or public folder keeps the brand visible in tabs and bookmarks.
- **Let users suggest answers with editable content** [general] Making an FAQ section editable invites visitors to contribute answers, which can surface questions the team has not considered.
- **Set input mode so mobile shows the right keyboard** [general] The input mode attribute opens a keyboard suited to the field, such as numeric or email, which makes mobile entry easier.

## 2 Ways of Building Websites (whosajid, Kkjpvfwhv-c)
- **Design web apps for simple, task-focused use** [web app] A web app is judged by how easily people complete actions, so the interface should be simpler and more functional than a marketing page. It also needs to be fast and work well on mobile.

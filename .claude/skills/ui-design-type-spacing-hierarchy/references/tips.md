# ui-design-type-spacing-hierarchy: full tip list

51 tips distilled from the STA-518 catalogue (YouTube: @whosajid, kolejain). Grouped by source video. Rationale is the catalogue summary, not a transcript.


## Why the 60-30-10 Rule is RUINING Your UI Designs (kolejain, 66oOi9OLMCw)
- **Scale button tone with importance, from ghost to primary** [general] Making the most important action the darkest gives an obvious priority order across ghost, secondary, and primary buttons.
- **Step text tone down from headings to body to subtext** [general] Graded text tones create hierarchy while keeping the bulk of the copy comfortable to read. Reserve the strongest tone for headings.

## The stupid simple way to learn UI/UX design in exactly 10 minutes (kolejain, 9WVt1CelBfg)
- **Group related elements with proximity spacing** [landing page] Placing the heading and subtext closest, then the eyebrow, then the buttons, tells the eye which items belong together. Spacing alone creates the grouping.
- **Use color or opacity instead of size to create hierarchy** [landing page] Two lines at the same font size can still differ in importance when one is slightly faded. Lowering opacity pushes secondary text back without shrinking it.

## Every UI/UX Concept Explained in Under 10 Minutes (kolejain, EcbgbKtOELY)
- **Build hierarchy with size, position, and color** [general] Contrast between big and small or colorful and plain sets what the eye reads first, so a flat card can be turned from a spreadsheet into a design.
- **Make the most important item large and bold** [general] Otherwise the key item blends in with smaller secondary details such as dates, so size and weight should match importance.
- **Place price at the top right in an accent color** [general] Setting the price apart by position and color draws the eye to the most decision-relevant value.
- **Use generous white space** [general] Letting elements breathe matters more than fitting to a grid, and it keeps a page calm.
- **Set font size and line height for each text role** [general] Headings, subtext, and buttons each need their own size and line height so the text system is consistent.
- **Use consistent spacing between items** [general] Equal gaps, such as 32 pixels between sections, give the layout a steady rhythm.
- **Group elements that belong together** [general] Placing an announcement with its text, or a title with its subtext, creates structure and is another form of hierarchy.
- **Base spacing on a four-point grid** [general] Multiples of four can be halved cleanly, which creates consistent spacing across a design.
- **Use one sans-serif typeface** [general] A single well-chosen sans serif handles nearly every need, so mixing fonts adds effort without much gain.
- **Tighten letter spacing and line height on large headings** [general] Loose headline spacing makes large text look unrefined, and slightly negative tracking with tighter leading makes it feel professional.
- **Limit font sizes to a small set** [landing page] Landing pages usually need no more than about six sizes, which keeps the type scale readable.
- **Keep text sizes small in dashboards** [dashboard] Dense dashboards rarely need text larger than about 24 pixels, so the type range should shrink to fit the information density.

## Everything you need to know about Mobile App UI’s in 8 minutes (beginner friendly) (kolejain, Gfsd8NNuD9g)
- **Keep type and spacing near desktop scale instead of shrinking them** [mobile app] Phone base type is often larger than desktop base type, so squeezing content into a small screen with tiny text is the wrong instinct. Scale and spacing should stay readable.
- **Avoid nesting cards inside cards and group with white space instead** [mobile app] Double-nested cards create padding on padding, which cramps the space available. Grouping with white space often achieves the same separation without the extra container.

## The 3 dashboard UI flaws that give away you've NEVER built one (kolejain, Ksx9C2-3yMo)
- **Tuck infrequent actions into a popover** [general] Rarely used features such as sharing do not need permanent space in the table. A popover keeps them reachable without sending the user to another page, and the primary action stays visible at the top.
- **Reveal secondary row actions on hover with a tooltip** [general] Secondary actions such as removing a user matter less than the primary ones, so they can appear only when the user looks for them. Pairing the hover reveal with a tooltip keeps them discoverable.

## 5 SaaS UI/UX mistakes that SCREAM you Vibe Code (kolejain, PDcQJOPby1k)
- **Emphasize the price over the plan name** [SaaS web app] Users care most about the monthly cost, so a larger price with a smaller name shifts the hierarchy toward the decision point.

## The one thing vibe coding CAN’T fix about your website (kolejain, RCneB_MQ7qs)
- **Pair the sans serif with a serif for personality** [landing page] A serif accent adds character, much like a printed menu, without giving up a readable sans for body copy. Mixing the two avoids a plain, generic feel.
- **Use bold, left-aligned type over an image for the CTA** [landing page] A large bold call to action on a background image gives the closing section weight. Left alignment keeps it grounded and modern.
- **Split headline lines and mix typefaces for interest** [landing page] Breaking a heading across lines and combining sans and serif creates rhythm and personality. It gives the headline more character than a single plain style.
- **Set buttons at least twice the heading-to-subtext distance** [landing page] Leaving more space between the subtext and the buttons than between the heading and subtext separates the call to action from the text. It also respects the large heading's baseline.

## 4 UI Design Hacks to KILL boring designs (kolejain, SfX43uIubj4)
- **Leave breathing room around decorative elements** [general] Generous spacing keeps illustrations reading as context rather than clutter. Adding one more element can push a playful layout over into cluttered.

## Everything you need to Design macOS Apps EXACTLY like Apple (beginner friendly) (kolejain, Vy0KKvZJRH8)
- **Keep the top band clear for window dragging** [desktop app (macOS utility)] The top roughly 50 pixels usually drag the window, so cluttering that strip with actions hurts usability and makes the header feel cramped.
- **Hide details until the user asks for them** [general] Progressive disclosure keeps the screen focused, so data like metadata appears only when a user clicks into an item.
- **Question every element before adding color or effects** [general] Starting from the minimum UI that lets the content stand out prevents decoration from competing with it.

## The 4 Levels of Landing Page UI/UX Design (kolejain, eMMiLeo_UGI)
- **Use one font family and build hierarchy through size and weight** [landing page] Sticking to a single typeface keeps the page coherent, but headings still need clear steps in size and weight to guide the eye.
- **Give key navigation actions more visual weight than ordinary links** [landing page] When every menu item looks the same, visitors cannot tell which action matters. Emphasizing the sign-up action and main links creates a clear path.
- **Build hierarchy with color and size together** [landing page] Pairing a size change with a color change makes the most important text stand out. Two cues are clearer than one.
- **Keep the headline from overpowering the subline** [landing page] A headline that is too dominant can make the supporting line feel lost. Balancing their scale keeps the message readable as a unit.
- **Use slightly looser spacing for balanced typography** [landing page] A little more space between lines and elements helps the type feel balanced and easier to read. Careful width control keeps text lines well shaped.

## The secret behind weirdly perfect UI designs (kolejain, neE6wOuBIP8)
- **Differentiate dense content with avatars and grouping** [general] Visual markers such as avatars and grouping by due date let people find an item quickly, so density works for the user instead of against them. Varied content is easier to scan than a uniform wall of text.
- **Create emphasis by contrasting an element with its neighbors** [general] Making one chip bolder or more colorful does little when its neighbors look identical. Changing the surroundings, such as being the only colored item, makes the element stand out.

## The 80% of UI Design - Typography (whosajid, 9-oefwZ6Z74)
- **Make the title bigger and bolder than the rest of the text** [general] Size and weight are the most direct way to show what the user should read first. A stronger title gives the feed a clear entry point.
- **Add hierarchy to list items with size, weight, and color together** [general] A list where every line looks the same reads as a blob of text. Making the title strong, the username smaller and quieter, and the action button lighter gives each piece a clear role.
- **Build hierarchy from a few font sizes and let weight and color do the rest** [general] Combining weight and color with size creates a lot of contrast without a large type scale. A small set of sizes keeps the UI calm and easier to maintain.
- **Pick one base font size and only deviate by a couple of pixels** [general] Designing most of the interface at one size, such as 14 or 16 pixels in regular weight and full color, keeps text consistent. Exceptions are reserved for titles and headings that need to stand out.
- **Define type styles once as global variables** [general] Storing weight, size, line height, and family as named values makes the type system easy to reuse and change. Setting these values in one place keeps every screen consistent.
- **Let line height provide spacing below text instead of extra margin** [general] Line height adds space around each line of text automatically, which separates a title from the content below it. Relying on it reduces manual gaps and keeps text blocks consistent.
- **Style text for visual hierarchy, not for document structure** [general] Heading tags describe the document, but what the user focuses on depends on the design. Judging by the user's attention and emphasizing that text gives the page the right visual order.
- **Zoom out to check font sizes against neighboring elements** [general] Font size is relative, so a heading that looks right alone can compete with nearby text. Viewing the whole interface shows whether the balance works.
- **Lighten the font weight when a bold heading feels harsh** [general] Heavy type can strain the eyes when it is large, so reducing the weight can make a strong size more comfortable to read. Adjusting weight and size together often works better than either alone.

## The Golden Rule of UI Design (whosajid, 9zt__YPULm8)
- **Make text easy to scan with headings and bullet points** [general] Users skim pages rather than read them, so clear headings and short lists help them find what they need quickly. Visual hierarchy guides the eye through the content.
- **Make the best option the most obvious one** [general] Users tend to click the first reasonable option they see, and if that is wrong they retry. Emphasizing the correct choice prevents that backtracking.
- **Give the product name and price clear hierarchy** [e-commerce] The name and price are the most important details, so they should be styled to stand out from secondary information. Clear hierarchy helps the user understand the offer at a glance.

## 23 Hacks about Building Websites (whosajid, AmY3db_Qs94)
- **Offset underlines so descenders stay readable** [general] Moving the underline lower with text underline offset keeps the underline from cutting through letters.

## The Easy Way to Design Premium Websites (whosajid, DBJoepxxQdg)
- **Pick a display typeface with character and a neutral body face** [general] Replacing one default font for everything with a headline face that has personality, plus a readable face for body text, gives the page a voice. Each typeface should have a clear job.
- **Use one consistent scale for spacing and type** [general] Values that follow a single proportional scale look intentional, while random values feel cheap even when viewers cannot name why. A side-by-side toggle makes the difference visible.

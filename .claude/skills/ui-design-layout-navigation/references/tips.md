# ui-design-layout-navigation: full tip list

55 tips distilled from the STA-518 catalogue (YouTube: @whosajid, kolejain). Grouped by source video. Rationale is the catalogue summary, not a transcript.


## The stupid simple way to learn UI/UX design in exactly 10 minutes (kolejain, 9WVt1CelBfg)
- **Keep the image focal point clear of overlapping elements** [landing page] Placing text above, below or to the side of the focal point leaves the image unobstructed. The open area then gives the visual room to show.
- **Keep hero backgrounds uncluttered so text stays readable** [landing page] A busy background makes the text harder to read and the page chaotic. A calmer image supports the message.
- **Choose a layout pattern based on what the content must do** [landing page] A profound statement suits centered text with lots of space, while a feature list needs supporting visuals. Matching layout to the content's job keeps the design purposeful.
- **Use a bento grid when many features must all be seen** [landing page] A bento grid keeps every feature visible as the user scrolls, rather than letting some get lost in a long row. It suits content with many items.

## Every UI/UX Concept Explained in Under 10 Minutes (kolejain, EcbgbKtOELY)
- **Use containers to group related items** [general] A box around some options tells users which items belong together and which do not, without any explanation.
- **Lead a card with an image for color and scanning** [general] A top image adds a pop of color and makes repeated items easier to scan.
- **Treat the 12-column grid as a guideline** [general] Custom pages often break the grid for good reasons, so the grid should serve the layout rather than dictate it.
- **Use column grids for repeating content and responsive behavior** [general] Galleries, blogs, and other repeating content benefit from defined column counts, such as eight on tablet and four on mobile.

## Everything you need to know about Mobile App UI’s in 8 minutes (beginner friendly) (kolejain, Gfsd8NNuD9g)
- **Replace a desktop sidebar with a bottom bar of three or four key links** [mobile app] A floating bottom bar keeps the most important destinations within thumb reach. Five links is the upper limit, and three or four is ideal.
- **Turn an overcrowded sidebar into a home page** [mobile app] When there are too many sidebar items to fit in a bottom bar, a home page can surface recent items at the top and counts or actions on the side. This avoids a lopsided screen.
- **Use the cleared bottom area of a home page for search or a primary action** [mobile app] Removing the sidebar frees the bottom of the screen for a large search bar or action button that is easy to reach. Apps such as Notion use this placement.
- **Choose one scroll direction per section** [mobile app] On a phone, a section can stack vertically or scroll horizontally, but not both. Choosing one direction per section is a useful rule when adapting dashboards for mobile.
- **Give each screen one purpose and add new things with a new page** [mobile app] Settings should only contain settings, and an editor should only contain the editor. Adding a new action by opening another page keeps each screen focused, with the home screen as the notable exception.
- **Hide persistent navigation and show task-specific actions while editing** [mobile app] Limited space means actions should appear only when needed. Opening a note hides the navigation bar and shows formatting and sharing actions, and template selection reduces the screen to confirm and close.

## The 3 dashboard UI flaws that give away you've NEVER built one (kolejain, Ksx9C2-3yMo)
- **Truncate long text and dim inactive table rows** [general] Truncating long cells gives other columns room to breathe. Shading inactive or deactivated rows tells users at a glance which records matter.
- **Show time-sequenced data as a timeline instead of a table** [general] A table sorted by time hides the sequence, while a timeline makes it easy to follow. The timeline can sit in a sidebar pop-out or beside the table.
- **Add a summary chart above time-based activity logs** [general] A chart that rolls up timestamped events shows the trend immediately, so users do not have to scan the timestamp column. It complements the detailed log rather than replacing it.

## 5 SaaS UI/UX mistakes that SCREAM you Vibe Code (kolejain, PDcQJOPby1k)
- **Align the sidebar left and tighten its spacing** [SaaS web app] A left-aligned, compact sidebar reads as deliberate and keeps navigation close together.
- **Move secondary links into a popover** [SaaS web app] Tucking rarely used links behind a click clears the sidebar for the links people actually use.
- **Organize growing pages with tabs** [SaaS web app] Tabs give a page room to add sections such as documents or integrations later without becoming crowded.
- **Use a two-column layout with small donut charts instead of KPI cards** [SaaS web app] A simple split layout with compact charts reads as more polished than a row of generic metric tiles.
- **Move bulk actions to the bottom of the list** [SaaS web app] Placing actions below the content keeps the rows clean and gives the list a clearer end point for controls.

## The one thing vibe coding CAN’T fix about your website (kolejain, RCneB_MQ7qs)
- **Layer larger images behind smaller ones and keep a margin around text** [landing page] Stacking big elements below and smaller ones on top makes a scattered arrangement look intentional. A safe margin around the text keeps it clear of the imagery.
- **Repeat the section pattern for a consistent rhythm** [landing page] Applying the same background, noise and text recipe to each section makes the page feel unified. Consistency makes the structure easy to follow.

## 4 UI Design Hacks to KILL boring designs (kolejain, SfX43uIubj4)
- **Center the core message and let supporting art frame it** [general] Removing the busy hero image and centering the headline makes the main message clear. Surrounding it with small contextual illustrations tells visitors what the product is for.
- **Push decorative elements toward the edges** [general] Elements that fade out as they move away from the center keep attention on the core content. Tilting or misplacing them can look off even when nothing is technically wrong.

## Everything you need to Design macOS Apps EXACTLY like Apple (beginner friendly) (kolejain, Vy0KKvZJRH8)
- **Keep the quick-capture window minimal** [desktop app (macOS utility)] A window that is only used briefly should carry just the drop area, one input, and a few buttons, with traffic lights removed.
- **Use the standard app layout of top actions, sidebar, and content** [desktop app (macOS utility)] Most Apple utility apps share this structure, so users already know where to look for global actions, navigation, and the main content.
- **Integrate window controls into the UI instead of a separate bar** [desktop app (macOS utility)] Placing traffic-light buttons in the top bar or sidebar lets them sit with other elements rather than looking bolted on.
- **Drop the sidebar when navigation is simple** [desktop app (macOS utility)] If the app is mostly browsing and searching, removing the sidebar frees room for large content such as images.
- **Use a floating search bar with a slide-out preview instead of a new screen** [desktop app (macOS utility)] Command-palette style results that open a new screen break the one-screen feel, while a floating bar and preview keep the user in place.

## The 4 Levels of Landing Page UI/UX Design (kolejain, eMMiLeo_UGI)
- **Balance the navigation bar across its width** [landing page] A nav bar with all its items pushed to one side feels lopsided. Centering or spreading the links evens out the composition.
- **Stack the hero vertically to give content room** [landing page] Moving the hero from a side-by-side split to a stacked arrangement gives the headline and visuals more space to breathe.
- **Build a logical top-to-bottom page flow** [landing page] Sections that follow one another in a sensible order guide the visitor down the page. Abrupt jumps between sections break that path.
- **Frame content with vertical guide lines** [landing page] Lines running the length of the page give the layout structure and make it scale to larger screens. They also tie sections together.
- **Use a bento grid when many items need room** [landing page] A row of four cards is cramped. A bento grid gives content more space and keeps it visually interesting.
- **Make section transitions flow into each other** [landing page] Where one section fades or segues into the next, the page reads as a continuous story. Hard breaks make visitors stop and reorient.
- **Shape the layout around the content instead of rigid lines** [landing page] A flexible layout that molds to the content feels more interesting than a grid of straight lines. Structure should serve the message.

## The secret behind weirdly perfect UI designs (kolejain, neE6wOuBIP8)
- **Align text hard left and prices hard right to create clean edges** [general] Pinning content to two strong edges, as a receipt does, makes a layout readable without dividers or extra padding. The edges do the structural work.
- **Place content on the edges of a card instead of filling empty space** [general] Adding more content to fill a sparse card looks strange. Each card has top, bottom, and side edges where elements can be anchored, which gives the layout a solid structure.
- **Add a subline to restore the bottom edge when icons get larger** [general] Swapping in larger icons removes the edge that the smaller text line provided, so content below loses its anchor. A subline brings that edge back.
- **Keep rows to a readable width instead of stretching them full screen** [general] Full-width rows keep the same edges but make the content harder to scan, because the eye has to travel far across each line. The same content reads more easily at a bounded width.
- **Use tabs and clean edges to group settings** [general] Tabs group related settings while the layout keeps clean edges, so the panel needs fewer boxes to stay organized.
- **Avoid nested borders, containers, and stacked radii** [general] Adding containers inside containers creates borders on borders and stacked corner radii that look cluttered. A single column edge can group content while removing the extra boxes.

## The 80% of UI Design - Typography (whosajid, 9-oefwZ6Z74)
- **Use size, color, and spacing to separate or group elements** [general] People read groups from proximity, size, and color, so these properties decide whether items look related. Adjusting them is how you make a title stand apart from the content beneath it.

## The Golden Rule of UI Design (whosajid, 9zt__YPULm8)
- **Keep primary actions in the same place on every screen** [general] Users build muscle memory for where actions appear, so consistent placement reduces searching. Keeping it consistent across screen sizes takes extra work but pays off in predictability.
- **Remove elements that do not earn their place** [general] Extra buttons, options, or animation that add no value compete with the key action and make the design harder to use. Each removal makes the rest clearer.
- **Flatten menus to reach the destination in fewer clicks** [e-commerce] An extra dropdown layer adds a decision before the user reaches the content. Replacing it with a direct route gets users to the catalog in two obvious clicks.
- **Keep product listing pages focused on the product image and price** [e-commerce] A large, clean product image with clear typography lets shoppers scan options quickly. Showing the most decision-relevant details first reduces the thinking required.
- **Group delivery details with the buy actions they relate to** [e-commerce] Information that belongs with the purchase decision should sit next to the buy controls. Keeping related items together reduces the search needed to decide.

## 23 Hacks about Building Websites (whosajid, AmY3db_Qs94)
- **Serve a cropped image to small screens** [general] Cropping an image for mobile and loading it through a source element with a media query shows the subject at a readable size on small devices.
- **Keep thumbnails at a fixed proportion** [general] Setting an aspect ratio lets an element scale with the layout while keeping its shape, which suits thumbnails and galleries.
- **Show objects that share properties in a table** [general] A table aligns shared attributes in columns, which is cleaner and easier to scan than a list.

## The Easy Way to Design Premium Websites (whosajid, DBJoepxxQdg)
- **Move the hero off a centered stack** [general] A fully centered headline, paragraph, and buttons is the safest layout and reads as generic. An off-center axis opens space for a stronger visual on the other side.
- **Break uniform card rows into a bento of varied tile sizes** [general] Equal-width feature cards look like a template, while tiles of different sizes add rhythm to the page. Each tile can show a live piece of the product.
